# 提示词增强

把下面的草稿改写成精炼、可直接发送的指令。不要回答或执行草稿描述的任务，不修改项目。

$ARGUMENTS

## 执行路径

1. 已知当前项目目录且 `get_project_context` 可用时，调用 `{ "workspacePath": "<当前项目目录>", "prompt": "<草稿>" }` 获取只读摘要（可传入草稿以获得更相关的模块与路径排序），供工具路径和无 Key 回退共同使用。它只读取项目清单、有界路径索引/模块摘要和 Git 元数据，不读取源码正文、选区或光标。不要把插件安装目录当成项目目录；路径未知时只使用会话里已经确认的项目资料。
2. `enhance_prompt` 可用时，调用 `{ "prompt": "<草稿>", "context": <项目摘要> }`。也可直接传 `workspacePath` 让工具自动采集，不要同时重复采集。结果第一段文本为增强提示词。
3. 工具不可用或返回错误时，使用已有项目摘要按以下规则就地改写。可调用 `get_enhancement_rules` 取得权威规则；不得使用其他文件或命令工具来执行草稿的任务。

## 增强规则

- 保留原始意图和硬约束，不回答、不执行任务，不扩大范围。
- 目标长度 ≤ 原文 1.5 倍，上限 2 倍；草稿清楚时原样返回或轻度润色。不增加通用检查清单或凭空的验收标准。
- 用项目类型、技术栈、目录结构和最近 Git 改动消除模糊指代，不把增强结果写成项目报告。
- Git 摘要只说明改动范围，不能证明代码行为或错误原因。资料缺失、截断或不可访问时保留原表述，不虚构事实。
- ZCode 没有编辑器选区、光标或当前文件概念，不引入这类上下文。模型选择只用于调用模型，与编辑器选区无关。
- 最多一个文件/符号锚点，仅在原稿明确指向它或确有歧义时使用。不罗列路径，不复制源码片段。
- 保持原稿语言、术语和语气；必要假设只用一句短语说明。丢弃密钥、令牌和密码。

## 输出

独立文本块中仅给出增强后的提示词，不带前缀、解释、标题或后缀。最多另加一句说明使用工具还是就地改写。桌面 ✦ 按钮安装后也可直接增强输入栏草稿。
