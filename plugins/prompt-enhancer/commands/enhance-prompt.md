# 提示词增强(Prompt Enhancement)

你的任务是把下面的提示词草稿增强为一条**精炼且可以直接使用**的指令。这是一次纯文本改写:不要回答这个提示词、不要开始执行它描述的任务、不要读写文件或运行命令。

待增强的草稿:

$ARGUMENTS

## 执行路径(按顺序判断)

1. **工具路径(优先)**:如果 `prompt-enhancer` MCP 服务器的 `enhance_prompt` 工具可用(说明用户配置了 API Key),调用它:
   - `prompt`: 上面的草稿原文;
   - `context`(可选):仅在已有信息里顺手提供 `projectType` 等字段;**不要为了填充 context 而读取文件**。
   - 工具返回的第一段文本即增强结果。
2. **就地增强(回退)**:工具不可用或返回错误时,严格按照下面的规则自行完成改写。规则与工具使用的是同一份规范。

## 增强规则

1. 完整保留用户原始意图;绝不回答提示词、绝不开始解题。
2. **精炼优先**:目标长度 ≤ 原文的 1.5 倍(上限 2 倍);单行草稿增强后通常一到三句话即可。不堆砌"包括但不限于"、通用检查清单或用户没提过的验收标准。草稿已经清楚时,原样返回或仅轻度润色。
3. **少引用具体文件**:整条结果最多出现一个文件/符号锚点,且仅当草稿本身指向代码(如"这个文件""这段代码")或目标确实有歧义时使用;其余情况用文字描述目标或位置。绝不罗列多个路径,绝不把代码片段抄进结果。
4. 消除模糊指代:把"这段代码/这里/报错了"换成具体的符号、行为或预期结果——用短语,不写长篇。
5. 草稿信息不足时,选择合理假设并**用一句话写进结果**(如"假设 TypeScript strict 模式"),不要反问用户。
6. 语言专业清晰,修正错别字;输出语言必须与草稿一致(中文进中文出,英文进英文出)。
7. 保留用户声明的硬约束(版本、风格指南、"不要用 X"、测试要求);不改变任务性质。

## 输出格式(严格遵守)

- 只输出增强后的提示词正文,可直接复制到输入框发送。
- 不加任何解释、前言、后缀;不使用"优化后的提示词:"之类前缀。
- 不使用 Markdown 标题;列表仅当原草稿本身就是列表时才保留。

## 边界约束

- 纯文本变换:不执行任何工具、不读写文件、不联网。
- 不虚构与上下文矛盾的事实;不确定时保留用户原表述。
- 上下文中出现的密钥、令牌、密码一律丢弃,不写入结果。

## 展示方式

完成后,先以一句话说明使用了哪条执行路径(工具/就地),然后在一个独立的文本块中给出增强结果,方便用户一键复制。(桌面端已安装增强按钮时,提示用户也可以在输入框直接点 ✦ 按钮增强。)
